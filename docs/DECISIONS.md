# 设计决策记录

这个项目的主要决策与来由，按时间记录。目的：让任何接手者（包括 AI）理解每个选择背后的取舍，而不只是看到结果。本项目为 AI 协作开发：架构方向、关键决策与验收由作者完成，实现由 AI 执行。

## 总原则

- **无人化优先**：目标是「给一个人名，出一支成片」，任何需要人手反复操作的环节都要消灭或降级为一次配置。
- **事实可核查**：人物史实不许只靠模型记忆，必须有资料层兜底、且生成与审查不用同一个模型。
- **目录驱动**：模板、音色、BGM 风格都是数据目录，新增条目不改代码；文档与工具读同一份目录，防漂移。
- **成本纪律**：能用免费档就不付费；每个付费点都要能算清单价（一首歌 12 日元、一支视频的模型费 2–5 日元）。

## 2026-10-24 · 音乐卡点：让视频迁就拍点网格

- 问题：BGM 和画面各走各的，蜡烛跳动与音乐节拍对不齐，廉价感主要来自这里。
- 想法（作者提出）：把视频的时间结构量化——蜡烛出现时刻吸附到半拍网格，音乐按同一 BPM 生成，两边同源于一个频率，整数倍对齐。
- 落地：脚本顶层 `bpm` 字段（默认 120，半拍 0.25 秒）；段时长限定 0.5 的整数倍，保证段界落拍；音乐提示词由工具按段界算出时间标记（高潮=巅峰段、安静=谷底段）。
- 验证：120 BPM 合成曲与重渲视频实测，音频峰值离网格平均 0.021 秒；存量歌曲（未按 BPM 生成）只能近似对齐（残差约 0.1 秒），解法是反过来把视频的 bpm 设成歌曲的速度，再平移第一拍。

## 2026-10-24 · BGM 与渲染分离

- 决定：音乐不进渲染，渲染出无声片，后期一条命令混音。
- 取舍：换一首歌只要几秒（重渲要 5 分钟以上），一支视频可出多版本，曲库放在仓库外。代价是多一步操作、漏混会发出静音版——用 produce 一键命令把这步包进去解决。

## 2026-10-24 · 音乐通道选型：为什么最后是「手动下载」

一条完整的否决链，每一步都有据：

- Suno 免费档：不可商用 + 下载受限，排除。
- Udio：全员禁下载，排除。MusicGen 权重 CC BY-NC，排除。
- Flow Music（Lyria）：订阅已含额度、质量够，定为主通道。
- 它的 API：模型本体（Lyria 3.5）有 Gemini API，$0.08/首，但没有免费层；作者的免费 key 调不动，开付费只为生歌不划算，工具做好备用（generate-music），不用。
- 本地 ACE-Step（开源可商用）：需 NVIDIA 显卡，作者的笔记本是 AMD 核显，生态不通，否决。
- 结论：Flow Music 网页生成 + 手动下载是目前约束下的最优解；全自动的口子（API 工具、带标签曲库）都预留好了，约束变了随时切换。

## 2026-10-24 · 配音：头尾两句式

- 痛点（作者提出）：全程配音必然「视频等配音」——中间每段时长定死，口播长短不可控，要么干等要么掐话。
- 解法（作者提出）：只配头尾。开头一句介绍人物（落在静止的片头卡上），结尾一句总结升华（盖在收尾定格上），中间保住音乐与标题的节奏。
- 补强：结尾配音反向对齐（在片尾前说完，视频永远不等它）；合成时人声自动压乐（sidechain，实测人声时音乐降约 20dB、说完恢复），而不是全程垫底小声。
- 音色纪律：全系列固定同一把嗓子（工具默认值定死），和「同一个歌手」是一个道理。

## 2026-10-24 · 风格路由：从写死到目录

- 问题：一套模板、一种嗓子、一种曲风套所有人，武将和文人一个味。
- 决定：模板、音色、BGM 风格拆成三套数据目录，脚本只写所选 id，由生成模型按人物气质选型；选错不存在的值有自动纠偏。新增风格 = 往目录加一条数据，不改代码。

## 2026-10-25 · 事实层：这条流水线缺了一层

- 发现（作者追问）：「人物资料保存在哪里？」——此前不存在。所有脚本都是模型凭记忆直接写的，年份与引句无任何兜底，这是全系统最大的风险点。
- 补法：新增资料层。生成前先从维基百科抓人物条目存档，生成时作为事实依据喂入；生成后由**另一个模型**对照资料逐项核查（出生年、关键点年份、引句真伪），错误以白名单补丁形式自动修正（只许动四类字段，防止审查者越改越乱），并留审查报告。
- 分工决定（作者拍板）：审查不由作者本人做（太麻烦），交给异源 AI + 维基为据；作者只在抽查时看报告。

## 2026-10-25 · 形态：从命令行到 Agent

- 追问（作者提出）：「每次指定人物都要敲 node 吗？」——工具思维 vs 产品思维的分界。
- 定版：node 命令降级为 Agent 的内核，日常交互走对话。通道选 Discord（作者主力工具；官方 Bot API；25MB 附件正好回传成片；斜杠命令与按钮适配选型交互）。
- 部署：Agent 常驻作者的 Windows 电脑（开机自启 + 状态文件断点续跑），聊天即界面。
- 面试官演示模式：同一 Bot 双模式。访客从预置人物目录选人（预渲染成片秒回）+ 限量 live 生成；现场点名可实时演示「选型 → 生成 → 异源审查当场纠错」全过程。设计详见视频工厂方案文档第 13 节。

## 2026-10-25 · 曲库：风格取舍与时间轴

- 试听裁决（作者）：爵士、国风、摇滚三个风格的 AI 生成效果不好听，砍掉——生成单与风格目录同步移除，生成器不再往那边选。
- 新增两风格补位：激昂史诗（epic-soaring，管巅峰/逆袭的燃）与久石让风（hisaishi-style，天空之城/千与千寻式钢琴＋管弦，管成长/回忆/天空感）。
- 时间轴定版：曲库曲子总长约 75 秒、主高潮 0:30–0:40、0:55 收尾提升。依据：视频只有 60–75 秒且混音取音频前段，老曲库实测 6 首高潮全在 105 秒开外，等于没有高潮。
- 曲库管理：音频不入 git（只存本地），元数据（时长/BPM/高潮点）由 scan-bgm 在本地测得并登记 manifest，远端看表选曲。

## 2026-10-25 · 曲库：新增游戏 OST 两风格

- 作者点名新增：轨迹燃曲（trails-battle，空轨/零轨式小提琴主奏＋摇滚乐队）与异刃史诗（xenoblade-epic，Counterattack 式管弦摇滚＋无词合唱）。曲库现行 7 风格。
- 异刃风破例保留合唱：Counterattack 的灵魂就在合唱，但只许无词哼唱（wordless），不许歌词与独唱，避免与旁白打架；若实测压旁白，再生无合唱版。

## 2026-10-25 · 配音：旁白形态定版

- 作者拍板：保持「头尾两句」——开头一句钩子、结尾一句升华，中间留给音乐与画面。不做全程旁白（信息量大但是另一种产品，且合成慢、语气翻车面大）。头尾两句是这个格式的识别度所在。
- 选角流程：audition-voice 全音色同台词试音 → 作者听审定 2–3 把常用嗓子 → 固定进音色库。引擎分工建议：edge 免费主力、Gemini 定制音色（elder/documentary）作精品线、ElevenLabs 克隆为后期品牌化选项。

## 2026-10-25 · 配音选角：不用男声

- 作者试听后决定（原话）：「不考虑男性的声音」。男声档案（yunyang/yunjian/yunxi/elder/documentary）保留在音色库里（老脚本兼容）但标注停用，生成器不再选。
- 女声阵容：edge 晓晓、晓菡 + Gemini 新增纪录片女声（documentary-f，Kore）与温润讲述女声（warm-f，Sulafat）；默认暂定 documentary-f，听审后再定正式默认。
- 附带诊断：作者机器上 edge 引擎试音全灭（原因被旧版试音工具的报错截断掩盖）；audition-voice 已加 edge 预检（装没装＋真合成一句），失败原因能直接说清。

## 2026-10-25 · 配音选角结果：定版晓晓

- 作者试听四把女声候选（晓晓、晓菡、Gemini 纪录片女声、Gemini 温润女声）后裁决（原话）：「只有 xiaoxiao 是女声，compact 那个还行」——定版 xiaoxiao（zh-CN-XiaoxiaoNeural）为唯一常用音色兼默认，其余候选一并停用。
- 至此配音阵容收敛为单音色：脚本 voice.style 实际只会落到 xiaoxiao；日后想重开选角，改 voice-profiles.json 的停用标注即可。

## 2026-10-25 · 自动选曲接通

- produce 合成前自动选曲（tools/pick-bgm.mjs）：按脚本 bgm_style 查曲库登记表，入池条件 = auto:true + styles 命中 + 文件在本机；按高潮贴合度（目标 40 秒）排序，前三名按人物 id 哈希挑一首（同人可复现、人间分散）。优先级：手动 --bgm > 自动选曲 > 等人工送歌；--no-auto-bgm 可关。
- 曲库全量入池：52 首全部补齐 styles（falcom-rock→trails-battle、counterattack-epic→xenoblade-epic 别名）并翻 auto:true；新曲登记时带风格默认 auto:true，不想被选的手动改回 false。
- Discord 侧：小结出现「BGM 状态：已自动配乐」即任务直接定稿，机器人不再索要 BGM；但自动配乐的任务仍可换曲——发来新文件即覆盖重混。
